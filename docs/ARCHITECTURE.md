# Архитектура ImageMini

## Обзор

ImageMini — одностраничное браузерное приложение (SPA + PWA) без серверной части обработки изображений. Все операции выполняются на устройстве пользователя: Canvas 2D и Web Workers для выбранных ресурсоемких задач.

```
src/
  lib/
    image-core.ts    — декодирование, ресемплинг, улучшение, трансформации
    image-job.ts     — скачивание файлов, суффиксы, File System Access API
    crop-geometry.mjs — геометрия рамки кадрирования и перевод координат через поворот/отражение
    editor-geometry.mjs — единый масштаб и расположение редактора, координаты указателя и стирание alpha слоя
    editor-text.mjs — редактируемые текстовые объекты, преобразование позиции и сборка для экспорта
    batch.ts         — (логика очереди пакетной обработки в pages/batch.tsx)
    app-context.tsx  — глобальные настройки (язык, тема, качество, формат, фон)
    i18n.ts          — переводы RU/EN
  components/
    app-shell.tsx    — шапка и навигация
    drop-zone.tsx    — drag-and-drop, Ctrl+V, выбор папки
    compare.tsx      — сравнение до/после (ползунок/рядом/стопкой), масштаб, статистика, действия
    work-image.tsx   — состояние текущего изображения + панель
    logo.tsx         — логотип
  pages/             — по одной странице на операцию
  components/editor-session.tsx — общий canvas редактора, история действий и учет незавершенных операций
  components/editor-viewport.tsx — общая область просмотра, Fit, масштаб, центрирование и панорамирование
  components/patch-workspace.tsx — два режима заплатки, выбор маски, донорское превью и экспорт
  components/layer-workspace.tsx — временный слой с трансформацией, мягким и жестким ластиками
  components/text-workspace.tsx — отдельные текстовые слои и настройки оформления
  components/retouch-workspace.tsx — прежние инструменты ретуши; в текущем интерфейсе не подключены
  lib/patch.mjs       — перенос донорской текстуры, feather и цветовая подстройка
  lib/patch.worker.ts — локальное применение заплатки в Web Worker
  lib/inpainting.mjs — ограниченная по размеру локальная гармоническая интерполяция для небольших дефектов
```

## Поток данных

1. **Загрузка** — `DropZone` принимает файлы (drag-drop, `<input type=file webkitdirectory>`, вставка из буфера). Файл попадает в `WorkImageProvider` (одиночный режим) или в очередь пакетной обработки.
2. **Декодирование** — `decodeToBitmap` использует `createImageBitmap(..., { imageOrientation: "from-image" })` (учёт EXIF-поворота). SVG проходит санитизацию (`blobToSvgSanitized`: удаление `<script>`, `foreignObject`, `on*`, `javascript:`) и растрируется через canvas.
3. **Обработка** — чистые функции над `ImageBitmap`/`HTMLCanvasElement`:
   - сжатие JPEG/WebP: `canvas.toBlob(mime, quality)`; PNG проходит lossless-пересжатие IDAT через `fflate`, с проверкой, что новый поток меньше исходного;
   - улучшение: LUT для яркости/контраста/гаммы, медианный 5×5 фильтр для шумоподавления, ограниченная локальным диапазоном резкость и HSL-десатурация;
   - ресемплинг: ступенчатое уменьшение (`steppedDrawToCanvas`) или сепарабельный Ланцош (`lanczosResize`, 3-лепестковое ядро);
   - заплатка: пользовательская маска задает область назначения, смещение указывает участок-источник. «Однотон» игнорирует цвет донора, сначала оценивает плавный световой градиент по границе выделения линейной моделью, затем гармонически сглаживает локальные отклонения. Значения внутри маски вычисляются заново по ее неизмененной границе, поэтому повторное применение не накапливает смешивание. «Текстура» переносит детали донора, подстраивая средний цвет и контраст каждого канала по локальному окружению; край плавно растушевывается.
4. **Вывод** — `canvasToBlob` → сравнение размеров → скачивание (`downloadBlob` или `saveToDirectory` через File System Access API) → ZIP для пакетной обработки (fflate `zipSync`).

## Предпросмотр и сравнение

- Страницы одной операции используют debounced preview. Ключ результата включает изображение и все влияющие на него настройки. При смене ключа старый preview сразу скрывается, ссылка на его URL освобождается, скачивание недоступно до готовности нового результата.
- Общий `CompareSlider` показывает оригинал слева («До») и результат справа («После»). Оба изображения вписаны в один кадр; доступны разделитель, расположение рядом/стопкой и увеличение до 300%.
- Старые asynchronous задачи preview отбрасываются через generation gate. PNG-worker можно отменить; синхронные Canvas/Lanczos и медианная фильтрация не прерываются в середине, но их устаревший результат не публикуется и не скачивается.
- PNG-оптимизация объединяет IDAT, распаковывает zlib-поток и кодирует его с выбранным уровнем 0–9. Если результат не меньше оригинала, сохраняется исходный PNG. Цветовые данные, прозрачность и прочие PNG chunks сохраняются.

## Ограничения canvas и честность

- `MAX_CANVAS_AREA = 268 435 456 px` (16384×16384), `MAX_CANVAS_DIMENSION = 32 768`. Функция `fitsCanvas` проверяет размеры до отрисовки; `suggestScaleDown` предлагает коэффициент уменьшения. При превышении изображение уменьшается с явным предупреждением пользователю, а не падает.
- Сравнение размеров всегда честное: если результат больше оригинала, интерфейс сообщает об этом вместо того, чтобы приукрашивать «экономию».
- Апскейл подписан как интерполяция (Ланцош), а не «ИИ».

## Редактор

- Редактор хранит рабочий canvas и текстовые объекты в общей `EditorSession`. Заплатка, примененные слои, кадрирование, поворот, отражение и действия с текстом используют общую undo/redo историю с лимитом памяти; исходное изображение остается неизменным. Сброс возвращает к нему после подтверждения и очищает временные выделения.
- `EditorViewport` задает единые координаты и масштаб для заплатки, слоев, трансформаций и текста. При 100% один пиксель изображения занимает один CSS-пиксель; Fit ограничивает изображение размерами области, сохраняет его пропорции и не увеличивает маленькие изображения. Текстовые слои хранятся как данные документа и компонуются на canvas только при экспорте или явном применении.
- Заплатка работает локально на копии и экспортирует результат с суффиксом `_edited`. Обработка ограничена 8 Мп на изображение и 1 048 576 пикселей в прямоугольной рамке выделения. Маска не меняет изображение; пиксели обновляются после отпускания выделения.
- Для точной работы в «Заплатке» и «Слоях» используется контрастный SVG-курсор-карандаш. Цвет (белый, красный, синий, черный или желтый) хранится в `localStorage` отдельно от настроек изображения. Zoom относится к холсту, сохраняет пропорции и поддерживает 25–1600%; перемещение доступно кнопкой «Рука» и удержанием Space. Кроме свободного лассо и прямоугольника есть точечное многоугольное лассо: двойной щелчок или щелчок у первой точки замыкает его, Esc отменяет построение, Backspace/Delete удаляют последнюю вершину. Во время лассо край рабочей области запускает плавный автосдвиг.
- Лассо и прямоугольник строят маску. При перетаскивании выделения интерфейс показывает контур донора и предварительную подстановку; после отпускания донор считывается с изображения до операции и не вырезается из своего места. «Однотон» восстанавливает освещение линейной оценкой по непосредственным соседям маски и гармонически сглаживает ее, не используя донорские цвета. Результат привязан к неизмененной границе и не накапливает яркость при повторе. «Текстура» согласует средний RGB и разброс каналов по соседнему окружению и применяет гладкую alpha-растушевку; алгоритм режима не менялся. Это локальная подстановка текстуры, не Poisson blending и не генеративное восстановление: неподходящий донор, сложный градиент или сложный повторяющийся рисунок могут оставить заметный след. «Слои» дают временную копию фрагмента с масштабом, поворотом, отражением, непрозрачностью и двумя режимами ластика, которые изменяют только прозрачность временного слоя. Завершенный мазок можно отменить отдельно.

## PWA

- `public/manifest.webmanifest` — имя, иконки (192/512 + maskable), цвета темы.
- `public/sw.js`:
  - precache: `/`, `/index.html`, `/manifest.webmanifest`;
  - network-first с fallback на кэш для остального (приложение открывается офлайн после первого визита).
- Регистрация SW — инлайн-скрипт в `index.html`.

## Настройки

`app-context.tsx` хранит в `localStorage` (ключ `imagemini-settings`): язык, тему, последнее качество/формат, цвет фона для JPEG, режим сжатия, флаги «не увеличивать» и «сохранять пропорции». Кнопка сброса в настройках возвращает значения по умолчанию.

## Локализация и темы

- `i18n.ts` — типизированный словарь RU/EN, переключение в шапке.
- Тема light/dark/system через класс `.dark` на `<html>`, палитра — OKLCH-переменные Tailwind v4 (индиго-синяя с бирюзовыми/лавандовыми акцентами).

## Обработка в Web Worker

- `image-processing.ts` передает RGBA-буфер обработчику `image-processing.worker.ts` с transfer list; основной поток не удерживает копию пикселей.
- Worker выполняет Lanczos-ресайз и улучшение, сообщает прогресс, а клиент завершает worker после ответа или отмены.
- Увеличение в странице изменения размера использует общую функцию `computeUpscaleSize` из `image-sizing.mjs`; допустимые множители ограничены 1,5, 2, 3 и 4. Размеры округляются до целых пикселей.
- После кодирования PNG проверяются фактические размеры через `createImageBitmap`; ошибка показывается, если браузер выдал размеры не те, что были запрошены.
- Предпросмотр улучшения ограничен 1200 px по длинной стороне. Полноразмерный результат вычисляется отдельно по нажатию скачивания.
- Редактор кадрирует исходный canvas: координаты интерактивной рамки переводятся из повернутого/отраженного рабочего пространства обратно в исходное изображение. Геометрия вынесена в чистый модуль `crop-geometry.mjs` и покрыта unit-тестами.

## Дополнительные состояния интерфейса

- Редактор сначала показывает результат, а сравнение с оригиналом включается отдельно.
- Режим сравнения автоматически выбирает расположение рядом для вертикальных и стопкой для горизонтальных и квадратных изображений. Выбор пользователя можно изменить вручную.
- Регулятор параметра сравнения дополнен числовым полем, которое синхронизировано с ползунком и ограничено теми же min/max/step.
- Пакетная очередь показывает миниатюры, состояние и размеры каждого файла, прогресс завершенных и ошибочных заданий, отдельное скачивание результата и общий ZIP.
